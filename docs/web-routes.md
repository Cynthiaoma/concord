# Dashboard routes and deep links

The dashboard uses **URL fragments** (everything after `#`) for its client-side routes. The API serves the same built web app for all dashboard pages; routing comes from `useRoute()` in [`apps/web/src/App.tsx`](../apps/web/src/App.tsx). Copy a **full https URL**, including the fragment, when sharing a non-secret view.

## Routes

| Fragment | Page | Notes |
| --- | --- | --- |
| `#/` or an empty fragment | Home / assets | Default route |
| `#/signin` | Sign in | Used for unauthenticated visitors |
| `#/signup` | Sign up | Availability depends on server sign-up policy |
| `#/settings` | Account and workspace settings | Requires a session |
| `#/a/<assetId>/reconciliation` | Asset reconciliation | Default tab if the tab is absent/unknown |
| `#/a/<assetId>/holdings` | Holdings | Asset id comes from the watched asset record |
| `#/a/<assetId>/actions` | Corporate actions | |
| `#/a/<assetId>/controls` | Controls | |
| `#/a/<assetId>/events` | Events | |
| `#/a/<assetId>/export` | Audit export | |
| `#/invite/<token>` | Accept a workspace invitation | Secret link; do not include in public issues |
| `#/reset/<token>` | Reset account password | Secret, one-use link generated by the operator CLI |

Replace placeholders with the actual asset id or token; angle brackets here are documentation placeholders, not URL characters. Routes `#/a/<assetId>` and `#/a/<assetId>/<unknownTab>` fall back to the **reconciliation** tab. Unknown routes fall back to home. Invites/resets only match when a non-empty token segment is present. Parsing happens when the browser's `hashchange` event fires; normal navigation preserves the current server origin.

## Query parameters (inside the fragment)

The parser splits the fragment at `?`; therefore use `#/signin?error=...` rather than `?error=...#/signin`.

| Parameter | Used by | Meaning |
| --- | --- | --- |
| `error` | Sign-in, sign-up and settings | Google sign-in/connection error code; `googleError()` maps known codes to safe user-visible messages (see `Auth.tsx`) |
| `linked=google` | Settings | Confirmation after a successful Google account connection |

Other query keys are parsed as `URLSearchParams` but have no documented user-facing route effect. Do not assume they are forwarded to the API.

## Support and security

- For an ordinary asset problem, include the **route path and tab**, a safe synthetic example such as `https://concord.example.com/#/a/ASSET_ID/holdings`, plus the observed error. Never attach real holder records, live auth tokens, or personal data.
- Invitation and password reset tokens are placed in the fragment, which **is not sent in the initial HTTP request or HTTP referer**. The client still reads the token and sends it to the API to accept the invitation/reset; it can also be exposed in browser history, pasted URLs, logs from client-side tools or screenshots. Treat the full link as a secret. Avoid posting it in tickets.
- Generate password reset links with `pnpm concord reset-link EMAIL`; the [CLI reference](cli.md#reset-link-email) documents the expiry and single-use rule. Configure `CONCORD_PUBLIC_URL` to your HTTPS origin so links point to the correct deployment.
- Navigating to a client route does **not** bypass server authentication or authorization: the API still enforces session and workspace access.
